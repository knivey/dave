# Safe-Site Host Split with LLM Safety Classification — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One imgsite deployment serves a default site (all content) and an optional safe site (selected by Host header) showing only libera-origin or vetted-safe images; img-mcp classifies every non-libera generation via an nsfw first pass + concurrent strict vetting, persisting and baking the verdict into the image.

**Architecture:** imgsite gains a `[safe_site]` config, a visibility predicate threaded through every read surface (gallery/search/details/assets/SSE), and per-network upload-response base URLs. img-mcp gains an nsfw flag on the existing enhancement JSON, a concurrent vet stage reusing the enhancement config machinery, `jobs.safety` persistence, and a post-generation EXIF chunk rewrite that bakes safety + provenance into the image before hashing/upload.

**Tech Stack:** Go 1.25, SQLite (sqlx + goose), FTS5 (unicode61 + trigram), TOML config, testify; webp RIFF chunk surgery (hand-rolled, mirroring imgsite's existing parser).

**Spec:** `docs/superpowers/specs/2026-09-26-safe-site-design.md` — read it before your task; the plan argues from it.

## Global Constraints

- **`omitempty` on every new `_dave_inject_*`/tool-input/meta JSON field** (AGENTS rule: non-omitempty fields become `required` in the advertised schema and break callers). `UploadMeta.Safety` carries `json:"safety,omitempty"`.
- Safety values are exactly `unknown` | `safe` | `unsafe`; NULL never occurs in `images.safety`; anything unparseable degrades to `unknown`, never elevates.
- Default-deny: on the safe site, NULL/empty network is invisible unless `safety='safe'`.
- Network comparisons are case-insensitive on BOTH sides (config list vs stored value, upload meta vs config list).
- The machine is slow: run each gate ONCE per task, never in loops. Anything worth keeping goes under `~/dev/`, never `/tmp`.
- Repo conventions: testify `assert`/`require`, table-driven tests, design comments for non-obvious decisions, `go fmt ./... && go vet ./...` clean, docs (AGENTS.md / example.toml / docs/image-site.md / README) updated in the same task that changes behavior.

## Review Focus

The five input classes most likely to bite, each pinned by its owning task's tests:

1. **NULL/empty-network legacy or imported rows on the safe host** — must stay invisible (default-deny). Pinned in Task 3 (query surfaces test matrix includes a NULL-network row with `safety='unknown'` and one with `safety='safe'`).
2. **Network casing drift** (`Libera` vs `libera` in config, stored rows, upload meta). Pinned in Task 2 (resolution helper table test) and Task 6 (upload base-url test with mixed casing).
3. **Non-webp output during EXIF rewrite** — WARN + skip rewrite, upload continues with meta safety. Pinned in Task 11 (rewrite test with a PNG fixture).
4. **Vet failure/timeout while generation proceeds** — job completes and uploads with `safety='unknown'`. Pinned in Task 9 (vet error table) and Task 10 (recovery re-vet only when empty).
5. **Safe-host SSE replay leak** — a reconnecting safe-host subscriber (`?since=`) must not receive events published before they were safe-visible. Pinned in Task 5 (replay-filter test).
